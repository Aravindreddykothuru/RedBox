1. Red Box in one page

Red Box is a website that recommends films. You rate a few films (or import your Netflix, IMDb or Letterboxd history), and it predicts what you will want to watch next, explains why, and keeps adding films released after its training data ends.

The main idea

No single algorithm is best for everyone: one model knows your long-term taste, another what usually comes next in a viewing sequence. Red Box lets five models each suggest about 40 films, then a learned ranker (LightGBM) decides the final order using 41 facts about each suggestion. A diversity step can mix the list up, and every film gets a reason. Because the models score your current history, a new rating changes the very next page without any retraining.

What makes it more than a model

  • Fair research: one chronological split, equal tuning budgets, test data used once, significance tests.
  • Explained picks: “Because you liked …”, and a per-signal breakdown of the ranker's score (TreeSHAP).
  • Cold start solved with ML: brand-new users get model forecasts; brand-new films are placed in the model's taste space from their story.
  • Keeps up after 2023: 3,146 newer films in six languages, more found daily, learning from every rating.
  • Production-grade app: real accounts, A/B testing, history import, group recommendations, 197 automated tests.

3. System architecture

What happens where

  • Research pipeline (offline). Everything heavy happens here once: preparing data, training, tuning, evaluating, and exporting the model bundle (the trained weights of five generators, the LightGBM ranker, film data, text vectors and forecasts). The bundle is uploaded to a private Hugging Face dataset; MovieLens's raw viewing histories are never included.
  • API (online). On first start it downloads the bundle onto its disk; afterwards it starts in seconds. It never retrains: each request reads the user's ratings from SQLite and the engine scores them in memory.
  • Website. Static pages from Vercel; the browser calls the API with the user's sign-in token (a signed JWT).
  • Daily jobs inside the API. New releases are fetched and added; app ratings of new films update their factors; posters are cached on disk.

From stars to “liked”

Recommendation is treated as ranking, not as predicting stars: a rating of 4 or more counts as “liked” (implicit feedback). This is how the app behaves too: it decides what to show first, not what score you would give.

No peeking at the future

Each user's history is split by time: the oldest 80% for training, the next 10% for validation (tuning, early stopping, training the ranker) and the newest 10% for the final test. The test set influences no decision, and is used exactly once.

Measured on the whole catalogue

  • Every model ranks every film the user has not seen (no sampled negatives, which inflate scores).
  • NDCG@10 (main metric) rewards putting the films the user actually liked next near the top of the list; also hit rate, recall, precision, MRR and MAP at 10, plus beyond-accuracy measures: catalogue coverage, novelty, intra-list diversity and exposure Gini.
  • Every model gets the same tuning budget (Optuna: up to 40 trials or 25 minutes on MovieLens).
  • Differences are tested per user with the Wilcoxon signed-rank test, Holm-corrected.

Highlighted: the five generators of the live Red Box hybrid. They can all score a user from their current history without retraining; LightGCN cannot (a new user would need graph retraining), so it stays in the research hybrid, which scores the same.

How the five deployed generators work

EASE (Steck, 2019). With the user–film matrix X, it solves for an item–item weight matrix B with a zero diagonal (a film may not predict itself):
P = (XTX + λI)−1,   Bij = −Pij / Pjj
A user's scores are their history row times B: one sparse product. Strong on long-term taste.
iALS (Hu, Koren & Volinsky, 2008). Every user u and film i get 64-dimensional vectors; liked pairs should score about 1, others about 0, with liked pairs weighted (1 + α) times more. For a new or changed history the user vector is solved exactly in one step (“fold-in”):
pu = (QTQ + αQuTQu + λI)−1 (1 + α) QuT1
SASRec (Kang & McAuley, 2018). Your liked films, in order (up to 200), become embeddings plus position encodings; two self-attention blocks (64 dimensions) read them, and the last position's output is compared with every film's embedding. Trained in PyTorch with a cross-entropy loss; served by an exact NumPy copy (tested to match PyTorch).
Markov chain. Counts how often film j is liked right after film i:
P(next = j | last = i) = count(i → j) / count(i)
Cheap and sharp at “what comes next”. MostPop adds what is popular, which matters for users with little history.

Formulas are simplified; Chapter 7 of the report gives the full objectives, settings and tuning ranges.

6. How a recommendation is made

1
Read your history. The API loads your ratings and imported watches from the database, in the order you met them. A film counts as liked at 4 stars or more, or if you watched it and didn't rate it lower.
2
Stage 1: candidates. Each of the five generators scores all 8,487 films for you, and its 40 best unseen films become candidates. They overlap, so the union is about 123 films. This set contains 43.8% of the films test users actually liked next, which is the ceiling for any ranker.
3
Describe each candidate with 41 features: each generator's normalised score, rank and “in its top 40”; how many generators agree; popularity, and popularity relative to your usual taste; similarity to the last film you liked; release year and 18 genres; how well the genres match your profile; how long your history is.
4
Stage 2: rank. A LightGBM model trained with LambdaRank (which optimises NDCG directly) orders the candidates. It was trained to put each user's validation-period likes on top, data the generators never saw, so it learns which model to trust when. SASRec's rank is its strongest signal (52% of the gain importance), then EASE's taste score.
5
Stage 3: diversity (optional). Maximal Marginal Relevance picks films one at a time, scoring λ·relevance − (1−λ)·similarity to films already picked. At λ = 0.8, accuracy drops 4% while variety rises 16%. The home page's Diversity slider sets λ.
6
Explain. Every film gets a reason (“Because you liked Interstellar”, “Matches your taste for Sci-Fi”). On the film page, TreeSHAP splits the ranker's score exactly into contributions such as “EASE: films liked together +44%”.
7
Real time. Nothing is cached per user: the next request uses your newest rating. On the 2 GB server this takes about 0.3 s. Requests take turns through one lock, because the scorers briefly hold the history being scored.

8. New releases after 2023

The models learned from MovieLens ratings, which end in October 2023, and a film without ratings cannot be scored by any collaborative model. Red Box solves this in four steps, without retraining until the last one.

  1. Arrival. Once a day the API asks Wikidata for this year's and last year's releases in English, Hindi, Telugu, Tamil, Kannada and Malayalam (English needs coverage in at least 8 Wikipedia language editions, which keeps the films people talk about). Each film's article must really describe that film; this check removed actor biographies, lists, and once a rainfall map. 3,146 films were in at build time.
  2. Story guess (item cold start). A ridge regression, learned on the 8,487 catalogue films, maps a film's MiniLM text vector to its 64 iALS factors (after van den Oord et al., 2013). Tested on 848 catalogue films hidden as if new: hit@10 18.9%, against 5.0% for comparing texts directly and 31.2% for the films' true factors.
  3. Warm-up. When app users rate a new film, its factors are re-estimated as in collaborative topic regression (Wang & Blei, 2011): the story's guess is a Gaussian prior and each rating is an iALS observation of the rater's taste vector.
    q = (c Σu pupuT + λI)−1 (c Σu rupu + λ qtext)
    NDCG@10 on the hidden films: 0.080 with the story only, 0.087 after 10 likes, 0.100 after 30 likes, against 0.125 when fully trained (λ = 30, chosen on validation data).
  4. Graduation. Once 20 app users like a new film (the same rule every catalogue film passed), retraining with the app's ratings makes it a regular film in all five models.

What we found

  • The hybrid beats the best single model on every dataset: +9.0% (MovieLens-1M), +8.3% (Amazon) and +15.9% (the app's models), all highly significant (p < 10−26; p = 1.3 × 10−87 for the app).
  • A tuned simple model beats the deep ones: EASE, a single matrix solve, beats NeuMF, Mult-VAE and LightGCN on both datasets, confirming published reproducibility studies.
  • MovieLens rewards rating order: 96% of test users continue the same rating session; trained on shuffled histories, SASRec loses 61% of its NDCG@10. For users who return days later, EASE wins. On Amazon this effect disappears, and the conclusions still hold.
  • Variety is cheap: the MMR slider trades a little accuracy for a lot more diversity.

10. How to use it

As a visitor

  1. Open https://redbox-recommender.vercel.app and create an account (email and password).
  2. Pick a few genres you like, then rate about ten films, or import your Netflix, IMDb or Letterboxd history instead.
  3. Home shows your Top picks (with a reason on every film and a Diversity slider), New releases for you with a language filter, Because you liked …, Hidden gems and Top 10 to watch next. Rate any card: the rows change on the next load.
  4. Open a film to see its story, Why it's here with the ranker's breakdown, and similar films by viewers or by story.
  5. Search by title, or describe what you want (“a slow-burn heist”, “time travel”).
  6. Watch together: add friends and a few films each likes; choose Everyone happy, Nobody unhappy or Someone's favourite.
  7. Switch the interface to Telugu or Hindi, and install it as an app from the browser menu.
  8. Model Lab shows every model's top 10 for you side by side; Results shows the research as interactive charts.

As a developer

# API and website locally (needs a model bundle in data/bundles/)
cd backend  && uv run uvicorn app.main:app          # http://127.0.0.1:8000/docs
cd frontend && npm install && npm run dev             # http://localhost:3000

# Reproduce the research (MovieLens-1M)
cd ml && uv sync
uv run recsys download ml-1m && uv run recsys prepare ml-1m && uv run recsys split -c ml-1m
uv run recsys tune -c ml-1m && uv run recsys benchmark -c ml-1m-tuned && uv run recsys hybrid -c ml-1m-tuned

# The app's models (MovieLens-32M) and their bundle
bash ml/scripts/train_app_models.sh               # prepare, train, export (CPU: a few hours, mostly SASRec)
uv run recsys newfilms -c ml-32m                  # new releases in six languages, with their evaluation

# Tests
cd ml && uv run pytest      ·  cd backend && uv run pytest      ·  cd frontend && npm run e2e

Main API endpoints (interactive docs at /docs): GET /recommendations, GET /recommendations/feed, GET /recommendations/new-films, GET /recommendations/why/{id}, POST /group, GET /search/semantic, GET /movies/{id}/similar, PUT /ratings/{id}, POST /me/import.
